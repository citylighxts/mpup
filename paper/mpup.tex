\begin{abstract}
Retrieval-Augmented Generation (RAG) systems rank passages by topical relevance, yet relevance and usefulness are not the same thing. Even a passage that matches a query may fail to help the model answer. Recent utility-aware RAG methods proven to be impractical because existing methods either fine-tune a reranker or retriever’s embedding model for every target LLM, or run the target LLM on every candidate passage at selection time, which takes up high cost, memory, and computation. Meta-Probing Utility Predictor (MPUP) is a method to predict LLM-specific retrieval utility without fine-tuning the target model.

MPUP combines 16 inexpensive signals: retriever scores, passage statistics, entity overlap, an NLI check against a hypothetical answer, the change in the LLM's next-token entropy, a cross-encoder score, and a ridge probe on the LLM's hidden state. A regressor trained on within-query deviations ranks the passages. On held-out test questions of ten datasets, MPUP reaches a Spearman correlation $r_s=0.356$ with the true utility, against 0.226 for dense similarity. The gain of $+0.13$ (57\% in relative terms) is highly significant (paired permutation test, $p<10^{-5}$; Holm-adjusted $p\le0.003$ in every dataset; $d_z=0.45$) and holds for datasets left out of training. With the top passage in the prompt, answer accuracy rises from 0.376 to 0.488. The hidden-state probe drives the gain: without it and the cross-encoder, $r_s$ is 0.280. A predictor trained on Qwen2.5-7B ranks passages for Mistral-7B at 0.313, against 0.210 for dense similarity, with no Mistral label. Extraction ran on a laptop within 6.4 GiB of MLX memory.
\end{abstract}

\section{Introduction}
Large language models (LLMs) are Transformer-based neural networks pre-trained on massive unlabeled text so that they are adapted to specific tasks through prompting rather than task-specific retraining~\cite{min2023}, making one model can do reasoning, summarization, and generation tasks that previously require separate architectures~\cite{chang2024}. LLMs are used in multiple areas, one of them is LLM for personalized tutoring and automated feedback in education~\cite{kasneci2023}. LLMs can also be used in reshaping professional practice, research workflows, and policy~\cite{dwivedi2023}.

LLMs often produce hallucinations which are outputs unfaithful to the source or factually incorrect~\cite{ji2023}, because their knowledge is stored and frozen at training time, making them cannot be corrected without retraining~\cite{huang2025}. Retrieval-Augmented Generation (RAG) addresses this problem by retrieving relevant documents from external sources and do generation on that retrieved evidence, so the model draws on up-to-date information instead of only memorized parameters~\cite{fan2024}. RAGs have multiple methods to retrieve the documents, one of them is traditional RAG which select documents purely by topical relevance where the contents match the queries, which works worse than RAG systems where the documents are selected by their utility for the model~\cite{zhang2026}.

Selecting documents or passages based on their utility in RAG is done by seeing whether the passage providing it as evidence measurably improves a LLM's ability to generate an accurate answer compared to answering without any evidence~\cite{zhang2026}. To measure this, two cases need to be compared. In the first, the model answers from its internal memory alone. In the second, the same model answers with a specific retrieved passage available to it. Both answers are scored by a standard correctness metric, and a passage counts as useful only when the second answer is more accurate than the first. Applying the same test to a large pool of candidates leaves only the passages that actually help that model~\cite{zhang2026}.

However, how can a practitioner estimate passage utility under realistic, low-budget conditions? Existing methods are too expensive for practical deployment, because they require a 32-billion-parameter teacher model to produce supervision~\cite{zhang2025b}, completely retraining the retriever's embedding model using complex objectives~\cite{sandhu2026}, or running the target LLM twice for every single query~\cite{zhang2025c}.

There are cheap alternatives method compared to LLM sampling. Semantic Perplexity (SePer) measures how useful a retrieved passage by observing how much its semantic perplexity changes after the passage is provided, but it still requires running an evaluation model, which adds computation and latency, making it less suitable for real-time passage selection~\cite{dai2025}. Another approach proposes a lightweight neural model that predicts passage utility for a target Question Answering (QA) model, but its predictor is trained for a specific QA model, making it difficult to apply to other QA models~\cite{perez2025}. Another method is a feature-based predictor combining Query Performance Prediction (QPP), perplexity, readability, and document quality features using linear regression to predict retrieval utility, but this method achieves relatively low accuracy for utility prediction, with Spearman $r_s \approx 0.20$--$0.24$ for retrieval utility on Natural Questions~\cite{tian2026}. Low accuracy and unapplicable solutions show that none of these methods has solved the problem yet.

Several other methods have been explored. There are LURE-RAG which introduces a lightweight LambdaMART reranker trained with a listwise utility loss to optimize context ordering, but relying on complex listwise utility supervision requires generating query and passage combinations, making the labeling cost expensive~\cite{chandra2026}. Another approach is RRPO, where passages selection treated as a sequential decision process trained via reinforcement learning directly from LLM feedback, which also which takes up big part of the memory and computation~\cite{wu2026}. Existing methods either require substantial memory and computational resources, or incur high costs.

Meta-Probing Utility Predictor (MPUP), proposed in this paper, closes the gap. MPUP is a method to predict LLM-specific retrieval utility which means it can select the most useful passages for models without fine-tuning any model. Instead of having the target LLM answer with and without every passage~\cite{zhang2025c} or scoring each passage with a separate evaluation model~\cite{dai2025}, MPUP evaluates a passage’s usefulness by looking at 16 practical clues, such as document statistics, meaning overlap, and agreement with a hypothetical answer. Three of them read the logits of an LLM through one forward pass per passage (logit probing), and one more is a linear probe on the hidden state of the same LLM. Another is the score of a cross-encoder. MPUP runs its LLM-based steps, one short generation per query and two forward passes per passage, with one shared model on a single GPU and does not train any LLM. The 14-feature core of MPUP, without the cross-encoder score and the hidden-state probe, is called MPUP-14 in the experiments. Section IV reports the measured memory footprint and extraction time.

Contributions of this paper are fourfold. The first is a predictor of the LLM-specific utility of a passage that needs no fine-tuning and no answer generation for each passage: MPUP combines 16 inexpensive signals, among them a ridge probe on the hidden state of the LLM and a cross-encoder score. The second is evidence on where the gain comes from. The 14 retriever, passage, overlap, NLI, and entropy features alone barely beat dense similarity ($+0.04$ in the first study), whereas the hidden-state probe lifts the gain to $+0.13$; document quality and NLI add nothing, and neither a smoothed training label nor a pairwise objective helps. The third is evaluation on test questions never seen during design: MPUP gains 57\% in relative $r_s$ over dense similarity ($p < 10^{-5}$, significant in each of ten datasets, also for datasets left out of training) and raises the answer accuracy from 0.376 to 0.488. The fourth is transfer and cost: a predictor trained on Qwen2.5-7B ranks passages for Mistral-7B better than dense similarity and a cross-encoder without any Mistral label, and the extraction runs end to end on a laptop with a peak of 6.4 GiB of MLX memory.

Remaining sections are organized as follows. Section II reviews related work on retrieval-augmented generation, utility-based passage selection, and lightweight utility prediction. Section III describes the proposed Meta-Probing Utility Predictor, covering the 14 features, the cross-encoder score and hidden-state probe added to them, the predictor architecture, and the model and hardware setup. Section IV presents the experimental setup, datasets, and evaluation metrics, followed by the results and analysis, while Section V concludes the paper and outlines directions for future work.

\section{Literature Review}
LLM can only use the knowledge it learned during training, and this knowledge cannot be updated without retraining. RAG solves this by first retrieving documents from an external source, then ask the LLM to write its answer based on those documents~\cite{fan2024}. In traditional RAG, passages are chosen by relevance, which means how closely their content matches the query.

However, a relevant passage is not always a helpful one. Recent work shows that choosing passages by their utility for the model gives better results than choosing them by relevance alone~\cite{zhang2026}. Utility is measured by comparing two answers from the same LLM. The first answer is written from the model’s own memory. The second is written with the candidate passage. Correctness metric scores both answers, and the passage is useful only if the second answer is more accurate~\cite{zhang2026}.

Utility also depends on what the model already knows. Passage may help one LLM but add nothing for another LLM that already knows the answer. So, utility belongs to a pair of passage and model, not to the passage alone. To estimate it in practice, we can either test the target LLM directly or approximate it with cheaper signals.

Methods that estimate passage utility can be grouped into four types. Utility estimation by large models or utility-trained retrievers is the first type. Zhang et al.~\cite{zhang2025b} distill the utility judgments of a 32-billion-parameter teacher LLM into smaller student models, and Sandhu et al.~\cite{sandhu2026} retrain the retriever’s embedding model with complex objectives so that its ranking follows utility. Both reach utility-aware selection, but at the cost of heavy training, and the former also needs a large teacher model to produce its supervision, which is hard to afford under low-budget conditions. Learned rerankers and selection policies trained from utility feedback form the second. LURE-RAG introduces a lightweight LambdaMART reranker trained with a listwise utility loss~\cite{chandra2026}, while RRPO treats passage selection as a sequential decision process optimized by reinforcement learning from LLM feedback~\cite{wu2026}. LURE-RAG depends on expensive query-passage labeling, and RRPO consumes substantial memory and computation.

Utility estimation by directly involving the target LLM is the third. Zhang et al.~\cite{zhang2025c} run the target LLM twice for every query to compare its behavior with and without the passage, and SePer measures how much the semantic perplexity changes once the passage is provided~\cite{dai2025}. Methods of this type are closest to the definition of utility as improvement over the model’s internal memory, but they add inference cost and latency at selection time, so they are less suitable for real-time use. Lightweight utility predictors form the fourth. Perez-Beltrachini and Lapata~\cite{perez2025} propose a lightweight neural model that predicts utility for a target QA model, yet it is trained for one specific model and is difficult to transfer to others. Tian et al.~\cite{tian2026} combine Query Performance Prediction (QPP), perplexity, readability, and document quality features in a linear regression, which is cheap but reaches only Spearman $r_s \approx 0.20$--$0.24$ for retrieval utility on Natural Questions.

MPUP is compared to eight previous studies which were based on six criteria, presented in Table~\ref{tab:mpup_positioning}. C1 is a lightweight model that runs on limited hardware. C2 is no fine-tuning of the LLM or the retriever. C3 is no additional LLM run for every query at selection time. C4 is utility estimation accuracy that is competitive with methods that probe the target LLM directly. C5 is a single predictor that works for several target LLMs without retraining. C6 is training on annotations that already exist in the dataset instead of labels generated by the target LLM.

Table~\ref{tab:mpup_positioning} shows how the studies differ. Methods that reach high accuracy through the target LLM~\cite{zhang2025c,dai2025} fail the lightweight and per-query cost criteria, while lightweight methods~\cite{perez2025,tian2026} either remain tied to one model or lose accuracy. LURE-RAG~\cite{chandra2026} is the one study that reports reusing a predictor, trained on the utilities of one LLM, for other LLMs (its fourth research question), but its labels come from running an LLM. MPUP meets C2 by design. MPUP still runs an LLM at selection time (one short generation per query and two forward passes per passage), so it meets C3 only in part. In 4-bit precision, MPUP meets C1, since the extraction ran end to end on a laptop with a peak of 6.4 GiB of MLX memory. For C4--C6 this paper gives only partial evidence. All partial marks are shown as $\sim$ in the table.

Utility-based selection is only useful if people can actually run it. Many practitioners have access to only a single GPU and a limited budget, not a training cluster. Methods that need very large models, retriever retraining, or two LLM runs for every query are out of reach for them. Methods that are cheap but tied to one LLM create another problem, because the predictor must be rebuilt whenever the LLM is replaced. Lightweight methods with low accuracy are also not helpful, since they often pick the wrong passages. Every barrier above would be removed by a predictor that is lightweight and does not have to be rebuilt for each new LLM, provided that its ranking is good enough to help. MPUP is designed for this purpose by combining many cheap features into one predictor, and Section~IV measures how good its ranking is.

\section{Methodology}
Fig.~\ref{fig:mpup_overview} shows the MPUP pipeline. For each query, MPUP first asks an
LLM $M$ to write one short hypothetical answer. Then, for every
candidate passage, it extracts 14 features from five feature families and adds two more, described below (16 features in total). Without these two, the predictor is called MPUP-14.
Next, the trained regressor maps these features to a utility score, and an
optional calibration step adjusts the scale of the score. Passages are ranked by the score, and the top passages are placed in the prompt
of the target LLM. No fine-tuning of the target LLM is ever needed, and the question does not need to be answered twice for every passage.


Passage utility measures whether a passage, given as evidence, improves
the accuracy of an LLM compared with answering without any evidence~\cite{zhang2026}. Let $q$ be query, $d$ candidate passage, and $L$
target LLM. Utility of $d$ for $L$ on query $q$ is the difference
in generation accuracy~\cite{zhang2026}:

\begin{equation}
    u(d;L,q)
    =
    \operatorname{Acc}(L(q,d))
    -
    \operatorname{Acc}(L(q,\varnothing)).
    \label{eq:utility}
\end{equation}

Where $L(q,\varnothing)$ is the answer of $L$ from its own memory alone,
and $L(q,d)$ is the answer of $L$ when it reads $d$.
$\operatorname{Acc}(\cdot)$ is a standard correctness metric. Passage
is useful only if reading it improves the model, which means $u>0$.
Zero utility means the passage adds nothing, and a negative value
means it makes the answer worse.

If we test a pool of candidate passages $\mathcal{C}$ in this way and
keep only the passages that help $L$, we obtain the gold utilitarian
set of $L$~\cite{zhang2026}:

\begin{equation}
    \widetilde{\mathcal{G}}_q^{(L)}
    =
    \{d \in \mathcal{C} \mid u(d;L,q)>0\}.
    \label{eq:gold}
\end{equation}

$\operatorname{Acc}$ is the average of relaxed exact match and
token-level F1 against the gold answers:

\begin{equation}
    \operatorname{Acc}(a)
    =
    0.5 \cdot \operatorname{EM}_r(a)
    +
    0.5 \cdot \operatorname{F1}(a).
    \label{eq:acc}
\end{equation}

Relaxed exact match counts an answer as correct when a gold answer
appears inside it as a token span. Relaxed matching is used because instruction-tuned
LLMs answer in full sentences, and strict exact match would mark most
of them wrong, which pushes almost every utility to zero. Values of $u$ lie in $[-1,1]$.

Building $\widetilde{\mathcal{G}}$ directly needs two LLM runs for
every query-passage pair, which is too expensive for real-time
selection. MPUP predicts the utility instead, so that passages in
$\widetilde{\mathcal{G}}$ are ranked first:

\begin{equation}
    \hat{u}(d;q)
    =
    f_{\theta}(\phi(q,d;M)),
    \label{eq:pred}
\end{equation}

where $\phi(q,d;M)\in\mathbb{R}^{16}$ ($\mathbb{R}^{14}$ in MPUP-14) is the feature vector and
$f_{\theta}$ is the predictor. $M$ is the LLM used for the
LLM-based steps: the hypothetical answer, logit probing, and the hidden-state pass. Either the target LLM $L$ or a fixed model can serve as $M$. In our experiments, $M$ is
Qwen2.5-7B-Instruct. Predictor $f_{\theta}$ is trained once and is not retrained when $L$ changes.

Table~\ref{tab:mpup_features} lists all 16 features. D1 describes how the retriever
scored the passage: its BM25 score (divided by the highest score of
the query), its dense similarity, its rank, and its score gap to the
next passage. D2 describes the passage itself: token length,
Flesch--Kincaid grade, and a source credibility score. D3 measures
meaning overlap. Entity overlap is the fraction of query entities,
found by spaCy, that also appear in the passage. Answerability is the
fraction of content words of the hypothetical answer that appear in
the passage. D4 checks faithfulness with a DeBERTa-v3-small NLI model.
Here, the passage is the premise and the hypothetical answer is the hypothesis, and we keep the entailment and contradiction probabilities.
D5 probes the LLM $M$. Next-token entropy is computed at the end of two prompts: the query alone
($H_{\text{base}}$) and the passage followed by the query
($H_{\text{ctx}}$). D5 features are the two perplexities $\exp(H)$
and the difference
$\Delta H = H_{\text{base}} - H_{\text{ctx}}$. Generated once per query, the hypothetical answer is shared by D3 and D4.

\paragraph{Hidden-state probe and cross-encoder} D5 summarises only the next-token distribution of $M$ in three numbers. MPUP also reads the hidden state of $M$. For every pair, $M$ receives the prompt that defines the true utility in Eq.~\eqref{eq:utility} (passage, then question), and the hidden state $h(q,d)\in\mathbb{R}^{3584}$ of layer 21 of 28 at the last prompt token is kept. Gold answers are never part of the input. Hidden states are centred within the query and standardised, and a ridge regression maps them to the within-query deviation of the training label, with the regularisation strength set to ten times the number of training pairs. Probe output becomes one more D5 feature. Inside a training set the probe scores are out-of-fold (five folds over queries), so the regressor never sees a probe score fitted on the same pair. MPUP also adds the score of a cross-encoder reranker (bge-reranker-v2-m3, 568M parameters, initialised from BGE-M3~\cite{chen2024m3}) as a fifth D1 feature, which gives 16 features; MPUP-14 is the predictor without these two additions. Neither addition fine-tunes $M$ or $L$. Layer and regularisation strength were fixed on the 100-question sample of Table~\ref{tab:datasets}, whose questions are excluded from every test set below.

Standardized features are passed to a regressor. Two kinds are considered. One kind, the reference configuration, is a gradient-boosted regression tree model (200 trees, depth 5, learning rate 0.05, subsample 0.8) trained on
the raw features. Another kind trains on within-query deviations: the
mean of the query is subtracted from every feature and from the label
before fitting, and at inference the candidates of the query being ranked
form that group. Much of the raw utility is an offset per query
(a question that the LLM already answers makes every passage useless),
which no reranker can use. Centred models spend no capacity on it, and their scores mean ``better or worse than the average candidate''. The
configuration of MPUP-14 is chosen from a grid of twelve (ridge regression with three
regularization strengths and gradient-boosted trees of three sizes, each
with and without centring) by nested leave-one-dataset-out, described in
Section IV.

Two kinds of label are used. In the main experiments the predictor is
trained on the true utility \eqref{eq:utility} of the training datasets.
When no LLM labels are wanted, it can instead be trained on labels derived
from existing annotations. RAGBench marks which sentences of each document were used to produce
the answer. For passage $d$, the label is the fraction of its sentences that are marked:

\begin{equation}
    \tilde{u}(d)
    =
    \frac{|S_d \cap S_{\text{used}}|}{|S_d|},
    \label{eq:proxy}
\end{equation}

where $S_d$ is the set of sentences of $d$ and $S_{\text{used}}$ is
the set of marked sentences. No LLM is run to produce these labels.
True utility \eqref{eq:utility} is computed with the same LLM $M$ acting
as the source LLM. Generated once per query, the no-context answer is reused for all passages of that query.

Optionally, $\hat{u}$ can be calibrated when labels from the target
LLM are available for $k$ passages. Coefficients $\alpha$ and $\beta$ are fitted by linear regression on these $k$ examples, and the calibrated score is

\begin{equation}
    \hat{u}' = \alpha \cdot \hat{u} + \beta.
    \label{eq:calib}
\end{equation}

Calibration changes the scale of $\hat{u}$, which matters for the threshold
$\tau$. Rankings do not change as long as $\alpha > 0$,
because the order of the scores stays the same. Calibration is not
used in the main results.

The LLM-based steps, hypothetical answer generation, logit probing and the hidden-state pass share one model $M$: Qwen2.5-7B-Instruct, run in bfloat16 on
a single NVIDIA RTX 6000 Ada GPU (48 GB). Sharing one copy avoids
loading a second 7B model, and full-precision weights mean that no
quantization error enters the probing and generation steps. Alternatively, the implementation can load $M$ in 4-bit NF4 with double
quantization to reduce memory; we report peak memory for both settings
in Section IV. Also available is an Apple Silicon backend that uses a 4-bit Llama-3.2-3B-Instruct through
MLX. Both the NLI model and the regressor are small and run without
quantization.

At inference time, MPUP makes one short greedy decode per query (at
most 48 tokens) for the hypothetical answer. For each passage it makes
one probing pass, one NLI pass, one pass of the cross-encoder, and one forward pass of $M$ for the hidden state (the implementation does not merge the latter with the probing pass), then applies the probe and the regressor. Passages are sorted by score, and the top $m$ ($m = 5$ by default, and $m = 1$ and $3$ in the answer experiments)
are written as numbered context before the query. Dropping passages with a score $\leq \tau$ is also supported. With the selected
predictor, which is trained on within-query deviations, the score is
relative to the other candidates of the same query, so $\tau = 0$
would drop roughly the less useful half of the candidates rather than
the passages with negative utility. No threshold is therefore applied.
Answer accuracy with the top one and top three passages is evaluated in Sections~\ref{sec:bigres} and~\ref{sec:crossllm}.

\subsection{Evaluation protocol}
All metrics are computed within each query and then averaged over queries, because a reranker can only order the passages of one query. Queries are used when they have at least two passages and their true utilities are not all equal (747 of the 1,100 queries with gold answers). Spearman correlation $r_s$ between the predicted score and the true utility serves as the main metric. Intervals are 95\% percentile bootstrap intervals over queries (2,000 resamples), and differences between methods are paired on the same queries. Splits are always by query, never by row.

Three kinds of numbers appear and should not be confused. The \emph{effect} is the paired difference $\Delta r_s$ between two methods (or $\Delta\mathrm{Acc}$ for answer accuracy): larger is better, and zero means no gain. The \emph{evidence} is the two-sided $p$-value of H$_0$: $\Delta=0$, reported next to a 95\% interval: smaller is better, and $p<0.05$ (after Holm correction when several datasets are tested) means that a difference of zero is unlikely, as does an interval that excludes zero. The \emph{size} of the effect is the standardised $d_z=\bar{\Delta}/s_{\Delta}$ over queries: larger is better, with about 0.2 small and 0.5 medium. Even a tiny $p$ can accompany a tiny effect when there are many queries, so all three are given.

Because the predictor is chosen from data, its score is estimated with nested leave-one-dataset-out. One dataset is held out. Among the other ten, each of the twelve configurations is scored by leave-one-dataset-out and the best is kept. Refitted on those ten datasets, the best configuration is scored on the held-out one, whose labels are not used for the choice. Choosing the best configuration on the held-out dataset itself would have reported $r_s=0.357$, which is 0.024 above the nested estimate. Since the grid was designed after an earlier run on the same questions with a smaller 3B model had shown that the reference configuration was weak, even the nested estimate is slightly optimistic. Results without any selection are also reported for the reference configuration.

\subsection{Setup}
Qwen2.5-7B-Instruct, run in bfloat16 on one NVIDIA RTX 6000 Ada GPU, serves as LLM $M$. Model $M$ writes the hypothetical answer, produces the probing features, and acts as the source LLM that defines the true utility (greedy decoding, at most 32 new tokens, relaxed exact match). Multilingual-E5-large provides the dense feature and the dense baseline. Baselines are BM25 and dense cosine similarity used alone as ranking scores.

\subsection{Larger study}\label{sec:big}
Five candidates per question leave little room to reorder, and 100 questions per dataset give each single-dataset test little power. Therefore, a second, larger study samples 700 questions from each of the eleven datasets with gold answers (all 125 of Bamboogle) with the same filters, and takes the top twenty BM25 passages instead of five when a dataset provides none. HotpotQA, 2WikiMultiHopQA, and MuSiQue keep their provided paragraphs. Together, the study has 7,125 questions and 128,467 query--passage pairs, every pair labelled with Eq.~\eqref{eq:utility} by the same $M$ and settings as above.

Every question is assigned once, by a hash of its identifier, to a development part (70\%) or a test part (30\%). Questions that appeared in either earlier sample always go to development, so no test question was seen while MPUP was designed. Bamboogle has almost no question left for testing and is excluded from the test averages. Development holds 5,031 questions and test 2,094, of which 1,641 are rankable. On development only, 24 variants are compared by leave-one-dataset-out: three tree ensembles (100 trees of depth 2 and 300 of depth 3 with learning rate 0.05, 500 of depth 4 with learning rate 0.03, all centred, subsample 0.8), each with or without the cross-encoder feature, with or without the hidden-state probe, and trained on the true utility or on its average with the change in log-probability of the gold answer. Fitted on the development questions, the best variant is then scored once on the test questions. MPUP is the chosen variant (500 trees of depth 4, true utility, cross-encoder score and probe); MPUP-14 is the configuration selected in the main study (100 trees of depth 2, true utility) without either addition. Two settings are reported: trained on the development questions of all datasets, and trained on the development questions of the other datasets only, so that neither the test questions nor their dataset were seen in training. Used alone, the cross-encoder is an additional baseline.

Mistral-7B-Instruct-v0.3, from a different model family, serves as a second target LLM. Every test question of the larger study and a hash-selected 40\% of its development questions (4,099 questions, 73,885 pairs) are labelled again with Eq.~\eqref{eq:utility}, now with Mistral answering, and the 14 features are recomputed with Mistral as $M$ (hypothetical answer and logit probing), together with its hidden states at layer 24 of 32. Test questions are the same as above; the variant chosen on the Qwen development questions is reused without new selection, and every score is against the utility for Mistral. Three uses are compared: MPUP fitted on Mistral's labels with Mistral's features and hidden states; MPUP fitted on Mistral's labels but with every LLM-side feature and the probe computed by Qwen, so that the model that is read differs from the target LLM; and the MPUP predictor of the Qwen study applied unchanged, without any Mistral label.

MPUP-14, selected by nested leave-one-dataset-out, reaches a macro-average $r_s$ of 0.333, against 0.289 for dense similarity, 0.117 for BM25, and 0.227 for the reference configuration. Over all 747 held-out queries, the paired gain over BM25 is +0.20 [+0.16, +0.24] and over dense similarity +0.04 [+0.02, +0.06]. \paragraph{Significance tests} Whether MPUP-14 orders passages better than dense similarity is tested as a hypothesis. H$_0$: the mean within-query difference in $r_s$ between MPUP-14 and dense similarity is zero. H$_1$: it is not zero (two-sided, $\alpha = 0.05$). Queries are the units, and the differences are paired. Per-query values are bounded and not normally distributed (Shapiro--Wilk $p < 0.001$ over all queries), so the test of Table~\ref{tab:main} is a paired sign-flip permutation test of the mean (200{,}000 random sign flips), which assumes no distribution; the Wilcoxon signed-rank and paired $t$-tests lead to the same decisions. For Table~\ref{tab:ablation}, whose per-query differences come from repeated cross-validation, the $p$-value is recovered from the bootstrap interval as in a paired $t$-test ($t = \hat{\delta}/\mathrm{SE}$, $\mathrm{SE}$ = interval width / 3.92, $n-1$ degrees of freedom); on the rows of Table~\ref{tab:main} this approximation differs from the permutation test by at most 0.02. Holm's correction covers the eleven single-dataset tests, and the pooled test is one test (the $p$-values are listed in Tables~\ref{tab:main} and~\ref{tab:ablation}). Over all 747 held-out queries, H$_0$ is rejected ($p = 0.001$, standardised effect $d_z = 0.12$). Per dataset, H$_0$ is not rejected after correction in any dataset: SQuAD ($p = 0.006$, Holm 0.071) and MuSiQue ($p = 0.016$, Holm 0.16) come closest, and the other nine datasets give no evidence of a difference. On the fresh questions with the frozen configuration, H$_0$ is rejected as well ($p < 0.001$, 693 queries). Rejecting H$_0$ means that a difference of zero is unlikely, not that the difference is large: the mean gain is +0.04 in $r_s$ and the standardised effect is small. Datasets of 44 to 94 queries each detect only a difference of about 0.06 to 0.17 in $r_s$ at 80\% power, so failing to reject H$_0$ there does not show equal performance.

\paragraph{Feature groups} Table~\ref{tab:ablation} shows the change in $r_s$ when one group is removed and the model is retrained, paired over queries. Retriever features (D1) matter most. With the selected configuration, the LLM probing group (D5) adds +0.02 [+0.00, +0.04] and the hypothetical-answer overlap (D3) adds +0.01 [+0.00, +0.03], although neither survives the Holm correction over five groups (adjusted $p$ = 0.065 and 0.122). Document quality (D2) and NLI (D4) add nothing measurable. Removing both groups together costs nothing either: retrained on D1, D3, and D5 only (selected configuration fixed, leave-one-dataset-out), the predictor reaches $r_s$ = 0.336 against 0.337 with all 14 features, and 0.335 against 0.336 on the second sample of questions. Retriever features alone (D1) only match dense similarity (paired difference +0.00 in both samples), so the gain over dense similarity comes from D3 and D5, and dropping either of them shrinks it. Which of the two matters more differs between the two samples. Most of the signal therefore comes from the retriever features, and each LLM-based group adds at most a few hundredths of $r_s$. Because the configuration was selected on the same datasets, the table is descriptive. Source credibility is constant (0.5) in all datasets, so effectively 13 features carry information.

\paragraph{Training without LLM labels} Trained only on the RAGBench annotation label, with no label from the target datasets, the reference-configuration predictor reaches a macro-average $r_s$ of 0.239. Compared with BM25 (0.117), the predictor is better on nine of eleven datasets, and it remains below dense similarity (0.289). \paragraph{Another LLM $M$} Earlier, the same pipeline was run with Llama-3.2-3B-Instruct in 4-bit precision through MLX on Apple Silicon (same questions and candidates, 719 held-out queries). Macro-average $r_s$ was 0.286 for MPUP-14, 0.256 for dense similarity, 0.110 for BM25, and 0.211 for the reference configuration. Because the two runs differ in the model, the quantization, and the hardware at the same time, the difference between them cannot be attributed to one of these.

\subsection{Larger study: MPUP on held-out questions}\label{sec:bigres}
On the development questions, the hidden-state probe is the addition that matters. Under leave-one-dataset-out, MPUP-14 without additions reaches $r_s$ = 0.269 (dense similarity 0.227, cross-encoder 0.257). Adding the cross-encoder feature gives 0.282, adding the probe gives 0.344, and adding both with the largest ensemble gives 0.346, the variant kept for testing. Averaging the label with the change in log-probability of the gold answer lowered every variant (best 0.320). With twenty candidates and more ties, all correlations are lower than in Table~\ref{tab:main}.

Table~\ref{tab:big} shows the single evaluation on the test questions. Trained on the development questions of all datasets, MPUP reaches $r_s$ = 0.356, against 0.280 for MPUP-14, 0.260 for the cross-encoder, 0.226 for dense similarity, and 0.106 for BM25. Paired over the 1,641 test queries, MPUP gains +0.130 [+0.116, +0.144] over dense similarity ($d_z$ = 0.45), +0.095 [+0.083, +0.108] over the cross-encoder ($d_z$ = 0.37), and +0.075 [+0.064, +0.086] over MPUP-14 ($d_z$ = 0.32); every sign-flip permutation test gives $p < 10^{-5}$. Table~\ref{tab:bigdata} lists every dataset, and Fig.~\ref{fig:forest} shows the gain over dense similarity in each of them. Gains hold on each of the ten test datasets: the Holm-adjusted $p$ is at most 0.003 against dense similarity and at most 0.012 against the cross-encoder in every dataset, in both settings. Trained without the dataset being tested, MPUP still reaches 0.351, and its gains over dense similarity (+0.124 [+0.111, +0.138]) and the cross-encoder (+0.090 [+0.078, +0.102]) barely change. Top-1 accuracy, the share of queries whose highest-scored passage has the highest true utility, rises from 0.459 with dense similarity to 0.618.

\paragraph{Size of the gain} Against dense similarity, MPUP raises the macro-average $r_s$ from 0.226 to 0.356, which is +0.130, or 57\% in relative terms; Table~\ref{tab:signif} gives the test against every baseline. The evidence is strong: the sign-flip permutation test gives $p < 10^{-5}$ over the 1,641 test queries (the smallest value that 200{,}000 flips can resolve), and the Holm-adjusted $p$ is at most 0.003 in each of the ten datasets. The standardised effect, $d_z = 0.45$, is close to a medium effect, and the gain over the earlier MPUP-14 (+0.075, $d_z = 0.32$) lies between small and medium. For selection, the passage with the highest true utility is ranked first for 61.8\% of the queries instead of 45.9\%, and the answer accuracy with one passage rises from 0.376 to 0.488, which closes about 40\% of the distance between dense similarity and the oracle (0.654). MPUP has the higher $r_s$ than dense similarity on 72\% of the test queries and is ahead in all ten datasets (an exact sign test over the datasets gives $p = 0.002$). For scale, Tian et al.~\cite{tian2026} report Spearman correlations of 0.19 to 0.26 for predicting retrieval utility on Natural Questions, so an absolute $r_s$ of 0.356 is not low, although their task (predicting the utility of a retrieved set across queries) differs from ranking the passages within a query. The gain is clear and consistent, but it is not a leap: the absolute $r_s$ of 0.356 is moderate, a gap of about 0.17 in answer accuracy to the oracle remains, and with three passages in the prompt the gain over dense similarity shrinks to +0.050.

\paragraph{Answer accuracy} Ranking quality matters only if the selected passages help the answer. For every test question of the larger study (2,093 questions in ten datasets, rankable or not), each method places its top one or top three passages into the prompt of Eq.~\eqref{eq:utility} (one block per passage), and $M$ answers. Table~\ref{tab:answer} gives Acc \eqref{eq:acc}, macro-averaged over datasets. With one passage, MPUP reaches 0.488, against 0.376 with dense similarity, 0.400 with the cross-encoder, 0.409 with MPUP-14, and 0.246 without any passage; the paired gain over dense similarity is +0.111 [+0.094, +0.128] and over the cross-encoder +0.088 [+0.073, +0.103] ($p < 10^{-4}$ for both). MPUP is ahead of dense similarity in all ten datasets, and after Holm's correction the difference is significant in five. With three passages, the methods move closer, because a good passage is more often among any three: MPUP reaches 0.494, ahead of dense similarity by +0.050 [+0.035, +0.065] and of the cross-encoder by +0.019 [+0.006, +0.033]. Selecting by the true utility (oracle) gives 0.654 with one passage, so a gap of about 0.17 remains.

\subsection{Second target LLM}\label{sec:crossllm}
Utility depends on the LLM. On the same 73,885 pairs, 49\% of Mistral's utilities are nonzero against 36\% of Qwen's, and the two utilities correlate at 0.60 within queries (centred Pearson). Table~\ref{tab:crossllm} scores every method against Mistral's utility on 1,714 rankable test questions. Fitted on 2,005 development questions with Mistral as $M$, MPUP reaches 0.373, against 0.247 for MPUP-14, 0.243 for the cross-encoder, and 0.210 for dense similarity; paired gains are +0.161 [+0.147, +0.176] over dense similarity ($d_z$ = 0.53) and +0.128 [+0.114, +0.142] over the cross-encoder ($d_z$ = 0.44), $p < 10^{-5}$, and the Holm-adjusted $p$ is at most 0.004 against both baselines in every one of the ten datasets. Even with fewer development questions than in the Qwen study, MPUP gains at least as much, so its gain is not specific to Qwen.

Reading Qwen instead of Mistral costs part of the gain but keeps most of it. With Mistral's labels but Qwen's features and probe, MPUP reaches 0.322, which is 0.050 [0.040, 0.061] below reading Mistral itself and still +0.111 [+0.098, +0.123] above dense similarity and +0.078 [+0.066, +0.089] above the cross-encoder. Without a single Mistral label, the Qwen predictor applied unchanged reaches 0.313, above dense similarity by +0.101 [+0.088, +0.114] and above the cross-encoder by +0.068 [+0.056, +0.080] ($p < 10^{-5}$ for both); it is ahead of dense similarity in all ten datasets (Holm $p \le 0.036$) and ahead of the cross-encoder in all ten, significantly so in seven. Transferred MPUP also beats MPUP-14 fitted on Mistral's own labels by +0.063 [+0.052, +0.076]. Qwen's own utility, which requires running Qwen with and without each passage and knowing the gold answer, ranks at 0.512, an upper reference for what one LLM can say about another. Fitted to labels shuffled within each query, the probe falls to 0.013, so its signal comes from the pairing of passages and utilities rather than from the hidden states alone.

With Mistral answering and the top passage in the prompt, MPUP (fitted with Mistral as $M$) reaches an answer accuracy of 0.479, against 0.380 with dense similarity, 0.391 with the cross-encoder, 0.399 with MPUP-14, and 0.280 without any passage (oracle 0.632). Paired gains are +0.098 [+0.084, +0.112] over dense similarity and +0.086 [+0.072, +0.100] over the cross-encoder; MPUP is ahead of dense similarity in all ten datasets and significantly so after Holm's correction in six. With three passages, MPUP reaches 0.475 against 0.424 with dense similarity and 0.450 with the cross-encoder.

\subsection{Cost}
Table~\ref{tab:memory} gives the peak GPU memory of the full pipeline (generation, labelling, probing, and NLI), measured on the datasets with the longest contexts (40 questions from MuSiQue and HotpotQA, batch size 32). Labelling and feature extraction for all twelve datasets (9,554 query--passage pairs, 7,997 of them labelled with the true utility) took 27 minutes in bfloat16 on one GPU, about 0.17 s per pair. Evaluation itself runs on the CPU. Over the whole extraction run for the second sample of questions (all twelve datasets), the peak in bfloat16 was 22.3 GiB. For the larger study (128,467 pairs, up to twenty candidates per question), labelling and the 14 features took 5.7 hours, with a peak of 25.7 GiB in bfloat16. Hidden states and cross-encoder scores for MPUP took a further 78 minutes (about 36 ms per pair) in a separate pass, which also scores the gold-answer log-probability used only during development. For Mistral (73,885 pairs), labelling and the 14 features took 3.8 hours with a peak of 27.2 GiB, and the hidden states a further 45 minutes. Reading the hidden state from the same forward pass as D5 would avoid that second pass, but was not implemented. The behaviour on a card or laptop with 8 GB of memory was not measured. On one Apple M5 laptop (24 GiB of unified memory, MLX), the same extraction for the first sample, with Qwen2.5-7B-Instruct in 4-bit precision and two layers of hidden states per pair, took 2.9 hours and peaked at 6.4 GiB of MLX memory over the whole run; the embedding and NLI models run outside MLX and are not counted.

\subsection{Limitations}
Results use one source LLM per run. Main estimates use 100 questions per dataset (390 for RAGBench), and the larger study uses up to 700, with its test questions drawn from the same datasets as its training questions; even in the setting that holds a dataset out, its development questions helped choose the variant. Intervals therefore reflect the variation among questions, not among models. Bamboogle is too small to keep test questions apart from the earlier samples and is missing from the test results of the larger study. Transfer between LLMs is tested with one pair only (Qwen2.5-7B to Mistral-7B, both 7B instruction-tuned models, in one direction), on the same questions; reading the target LLM itself was 0.05 better than reading Qwen, and other sizes and families may differ. Answer accuracy was measured only in the larger study, with the LLM that defines the labels answering, greedy decoding, and $m \in \{1, 3\}$. On the laptop, only the extraction of the 14 features and the hidden states was run, not the cross-encoder. Extraction time above includes the labelling with the true utility; the latency of selection alone (one generation per query, then probing, NLI, and the regressor per passage) was not measured. The probing prompt (passage, then query) is truncated at 512 tokens from the right, so for 35 of the 9,554 pairs (0.37\%) the query is cut off and their D5 features are computed without it. In the main study, candidate sets are small (4 to 20 passages), and in the datasets without provided passages they are the top five of BM25, which limits how much any reranker can change; the larger study uses twenty.

\section{Conclusion}
MPUP is a predictor of the utility of a retrieved passage for an LLM that combines 16 inexpensive signals, among them a probe on the hidden state of the LLM and a cross-encoder score, and does not fine-tune the target model. In a larger study with twenty candidates per question, MPUP ranks held-out questions clearly better than dense similarity and a cross-encoder reranker in every dataset ($r_s$ 0.356 against 0.226 and 0.260), also on datasets left out of training, and with the top passage raises answer accuracy from 0.376 to 0.488. The gain over dense similarity is +0.130 in $r_s$ (57\% in relative terms, $p < 10^{-5}$, $d_z = 0.45$, close to a medium effect), clear and consistent in every dataset but not a leap: the absolute $r_s$ is moderate, and a gap of about 0.17 in answer accuracy to the oracle remains. The hidden-state probe is the main source of the gain, since the 14 retriever, passage, overlap, NLI, and entropy features alone (MPUP-14) only slightly beat dense similarity. For a second target LLM, Mistral-7B, MPUP reaches 0.373 against 0.210 for dense similarity, and the Qwen predictor applied without Mistral labels keeps 0.313. Fitting on one GPU, the pipeline peaks at 21--26 GiB in bfloat16 and 6.4 GiB in 4-bit precision on a laptop. Future work should test transfer across more LLMs, sizes, and directions, measure the latency of selection alone, and evaluate on datasets that are not in the pool.
